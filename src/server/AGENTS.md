# src/server/ — the only layer that talks to Prisma

- Import the client as `import { db } from "@/server/db";`. Types/enums come from `@/generated/prisma/client` (e.g. `import { Prisma, type Transaction } from "@/generated/prisma/client"`). Never `new PrismaClient()` elsewhere.
- `db.ts` caches the client on `globalThis` outside production so `next dev` HMR doesn't leak pg pools.
- Every query filters by a `userId` resolved from the session (never from client input). Soft-deleted rows: filter `deletedAt: null`.
- Ad-hoc scripts outside the Next runtime need `import "dotenv/config"` before importing `db` (Next loads `.env` itself). Run them with `npx tsx --tsconfig tsconfig.json <file>`; on Windows dynamic imports of absolute paths need a `file:///` URL.
- `demo-user.ts` exports the fixed `DEMO_USER_ID` used by the seed; the demo account has 6 months of data (4 accounts, 2-level categories, budgets, recurring rules, a savings goal).
- Session: `getSessionUser()` from `@/server/auth` is the ONLY place that resolves the user (MVP: demo user; swap for Supabase there). It is wrapped in React `cache` and throws `UnauthorizedError` (→ 401) if missing.
- Route Handlers: `export const GET = handler({ query, body, params, status }, async ({ user, query, body, params, req }) => ...)` from `@/server/http`. Schemas are optional zod types and fully infer the ctx types. Return a value (JSON, `status` default 200), `undefined` (204) or a `Response`. Repeated query keys arrive as arrays; use `z.coerce` for numbers/dates.
- Errors: services throw `NotFoundError` / `HttpError(status, msg)` from `@/server/errors` (also re-exported by http.ts); `handler` maps ZodError → 400 `{ error, issues }`, HttpError → its status `{ error }`, anything else → 500 with a generic message (logged, never leaked).
- Testing handlers: `vi.mock("@/server/auth", ...)` then dynamically import `@/server/http`; use `// @vitest-environment node` (see tests/unit/http.test.ts).
- Services live in `src/server/services/*.service.ts` and take `userId` as the first argument. `account.service.ts` → `listAccountBalances(userId)` (active accounts + balance = initialBalance + Σ non-deleted amounts, via one `groupBy`); reuse it instead of recomputing balances.
- `dashboard.service.ts` → `getDashboard(userId, { month?, today? })` returns `DashboardData`. All math lives in the pure `dashboard.calc.ts` (ISO `yyyy-mm-dd` UTC date helpers, `monthContext`, `savingsRate`, `budgetPace`, `projectMonthEnd`, `pendingOccurrences`, `bucketCashflow`, sparkline series), unit-tested in tests/unit/dashboard-calc.test.ts — add new dashboard math there, not in the service. "Today" = `todayInTimeZone(user.timezone)`; currency/locale come from the user record (never hard-code). Income/expense = Σ `amountBase` of INCOME / −Σ of EXPENSE (transfers excluded); balance KPI = net-worth accounts (`includeInNetWorth`, not archived), transfers included.
- Raw SQL (`db.$queryRaw`): tables/columns are the quoted Prisma names (`"transactions"`, `"amountBase"`, `"userId"`), cast params (`${userId}::uuid`, `${iso}::date`), cast enums to text (`t."type"::text`). `@db.Date` columns come back as UTC-midnight `Date` → `utcToIso()`; SUMs come back as Decimal → `Number()`.
- Auto-categorization: pure logic in `services/categorization.match.ts` (`normalize`, `foldText`, `ruleMatches`, `suggestCategory`), tested in tests/unit/categorization-match.test.ts; `categorization.service.ts` only loads active rules + payees and writes. Order (docs §1): USER rules → known payee (exact `normalizedName`, has `defaultCategoryId`) → LEARNED → SYSTEM; within a source `priority` asc, then `createdAt`. Source beats priority. PAYEE rules fall back to the description when no payee is given. REGEX is case-insensitive, tested against normalized and raw text; invalid patterns never match (cached, never throw).
- `normalize()` is THE format for `Payee.normalizedName` and `CategorizationCorrection.payeeNormalized` (accents, case, punctuation, bank prefixes "COMPRA EN"/"PSE"/"PAGO", suffixes S.A.S./S.A./LTDA/E.S.P., trailing reference numbers). Rule patterns are compared with `foldText()` (no suffix/number stripping). Never write a second normalizer — the seed imports this one.
- `suggest()` is read-only; call `applyCategorization()` / `recordRuleHit()` when a transaction is saved with the suggestion (hitCount + lastHitAt). Call `recordCorrection(userId, { payee, categoryId })` when the user changes a category: rows go to `categorization_corrections`; at 2 for the same payee+category it upserts a LEARNED `PAYEE EQUALS` rule (priority 500) AND sets `Payee.defaultCategoryId` (the known payee is checked before LEARNED, so otherwise the rule would be shadowed).
- `transaction.service.ts` → `listTransactions`, `getTransaction`, `createTransaction`, `updateTransaction`, `deleteTransaction`, `restoreTransaction` (contract in src/features/transactions/AGENTS.md). Pure rules in `transaction.logic.ts`: `parseAmount` (decimals per currency), `signedAmount`, `moneyFields`/`resolveFxRate` (same currency only, else 400), `buildTransferLegs`, cursor encode/decode, `toTransactionDTO`. Reuse them for any other writer of transactions (recurring cron, CSV import) instead of re-implementing sign/FX rules.
- Keyset pagination with dynamic filters: build `Prisma.Sql[]` conditions, `Prisma.join(conds, " AND ")`, row comparison `(col, t."id") < (${v}::date, ${id})`, select ids only with LIMIT n+1, then hydrate with `findMany({ where: { id: { in } }, include })` and re-order in JS.
- Next 16: a second `next dev` in the same folder refuses to start while another one runs (lock in `.next/dev`). To test on your own port, `npx next build && npx next start -p 3200` works alongside it.
